# 0003. Схема данных мультипользовательская с самого начала

Хотя приложение разворачивается для одного пользователя, схема БД с первого дня несёт `user_id` на Продуктах, Блюдах, Записях и Целях, а также флаг приватности (private/public) на Продуктах и Блюдах.

**Контекст:** сейчас вход — минимальный JWT-логин с одним seed-пользователем. Но в задумке есть публичные/приватные Блюда и идеи на будущее (реклама/подписка для разных юзеров), которые требуют понятия «пользователь».

**Решение:** заложить `user_id` и приватность в схему сразу, не дожидаясь мультиюзера. Включение регистрации позже не потребует миграции модели данных и переписывания запросов.

**Почему это неочевидно:** будущий читатель увидит `user_id` повсюду в «однопользовательском» приложении и удивится. Это сделано намеренно — чтобы избежать дорогой миграции при переходе к мультиюзеру, а не по недосмотру.
